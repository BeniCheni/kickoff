# Architecture — the map, and the data flow

The public Kickoff app is a Vite + React + TypeScript app with no backend. The data is a
committed JSON snapshot; a script refreshes it; a workflow runs the script. The interesting
part is where the boundaries sit. Since October 2026 there is a second half, with a database
and a video store, described in "The full-stack half" below; everything above that section is
the public app.

## The data flow

```
ESPN scoreboard API ──▶ normalizeEvent ──▶ Zod at the boundary ──▶ snapshot (src/data/*.json)
      (public, no key)   scripts/providers/espn.ts   scripts/validate.ts        │
                                                                                 ▼
   app ◀── pull request ◀── commit ◀── report line ◀── diff against the last snapshot
                                        scripts/sync.ts          scripts/diff.ts
```

1. **Fetch.** `scripts/providers/espn.ts` implements a `FixtureProvider` interface — one
   method, `fetchWindow(from, to)` — against ESPN's scoreboard endpoint, per competition, in
   28-day chunks. It exists behind an interface so a second provider can be dropped beside
   it and made to disagree. `scripts/providers/espn-standings.ts` does the same for the
   league tables.
2. **Normalize.** `normalizeEvent` turns one ESPN event into one `Fixture`: the UTC instant,
   the venue zone, home and away, the status mapped from ESPN's vocabulary (an unmapped status
   throws — see [HONESTY.md](HONESTY.md) §5), and the time confidence (`exact`,
   `round_placeholder`, `tbd`). The fixture id is ESPN's event id namespaced by
   competition.
3. **Validate.** `scripts/validate.ts` runs every normalized row through the Zod schema in
   `src/lib/schema.ts`, all-or-nothing. A single rejected row aborts the sync.
4. **Preserve.** Hand-authored notes (a `note` field — the one thing a human may write, and
   only in a previous snapshot) are carried forward by id.
5. **Diff.** `scripts/diff.ts` compares the fetch with the committed snapshot inside the
   fetched window and produces the change list, the urgency flags, and the merge verdict.
6. **Prepare both, then write or refuse.** `scripts/sync.ts` orchestrates the shrink guard,
   both dataset validations, the writes, the exit code and the report line. Fixtures and
   standings form one authoritative snapshot: either fetch/validation failing aborts before
   any snapshot write. Git publishes the files together. A standings outage can delay valid
   fixture updates; future ancillary datasets do not join this boundary automatically.
7. **Commit and PR.** `.github/workflows/sync.yml` runs the script on a schedule, commits
   only when the report line says something changed, force-pushes one rolling branch, opens
   or updates one PR, and merges it with `gh pr merge --squash --auto` behind the required CI
   check. The `merge=auto|hold` verdict rides along in the report as a reader-facing signal;
   since 6 Sep 2026 it gates nothing, and no label holds a PR.
8. **Deploy.** `.github/workflows/pages.yml` rebuilds and redeploys the demo on every push to
   `main`, so a merged sync is live within minutes.
9. **Render.** The app imports the snapshot, validates it again at module load (a schema
   failure here means the generator and the app drifted apart — better a loud startup
   failure than half-understood rows), and renders.

## The map

```
src/lib/schema.ts          Zod schemas + the Fixture type. Identity lives here.
src/lib/time.ts            Timezone rendering. Formats instants; never parses wall-clock.
src/lib/competitions.ts    Competition metadata: colours, zones, US broadcasters, codes.
src/lib/fixtures.ts        Loads and validates the snapshot; grouping, the shared "still to
                           kick off" gate, the Next-up and Tonight's-slate planners.
src/lib/standings.ts       The league tables, same provenance rules.
src/lib/clock.ts           The one ticking clock: minute-aligned, catches up on focus.
src/lib/useNow.ts          The hook that reads it (useSyncExternalStore).
src/lib/lens.ts            The lens type and its total URL codec. Poster is the default.
src/lib/lensSelectors.ts   Pure per-lens data shaping (sub-lines, ticker, month cells, the
                           Poster week plan).
src/lib/theme.ts           The one theme decision + guarded storage. Broadcast dark-first.
src/lib/urlCodecs.ts       Total decoders for ?date= and ?only= — junk never crashes.
src/lib/useUrlState.ts     View state in the query string; push vs replace semantics.
src/components/            The skeleton: one FixtureRow, week and month views, the three
                           lens heroes, the Table, the banner, the ticker.
src/data/*.json            GENERATED by `npm run sync`. Do not hand-edit.
scripts/providers/espn.ts  Fetch + normalize, behind a FixtureProvider interface.
scripts/validate.ts        Zod at the boundary, all-or-nothing.
scripts/diff.ts            Snapshot comparison, urgency, the merge verdict. The safety net.
scripts/sync.ts            Orchestrator: fetch → validate → preserve → diff → write → report.
tests/                     DST boundaries, the normalizer, lens plumbing, the diff engine,
                           the honesty guards — one case per audited bug class.
```

## The full-stack half

Unreleased, and not the public site: it runs as a login-protected preview on Vercel until the
cutover in `docs/nextjs-migration-plan.md`. Four trees, one rule (generated video says what
it is, and a person publishes it):

```
studio/                 The admin and CLI. Local only. Imports a clip, runs the Card gate,
                        computes CLIP vectors, publishes to Supabase and Cloudflare R2.
                        Tests and offline runs use PGlite; --live is the only path to
                        Supabase.
web/                    The reader. Next.js on Vercel. Reads the published catalog through
                        Drizzle on a read-only Postgres role (server-side only).
packages/               @kickoff/catalog (the strict public row contract) and
                        @kickoff/demo (the labelled sample reactions and comments).
.github/workflows/      ci.yml (the required `verify` check), studio.yml, sync.yml,
                        pages.yml, preview-smoke.yml (a smoke after every Vercel deployment).
```

The database has three schemas that matter: `studio` (private tables), `catalog` (the two
views the reader reads, plus the two similarity functions) and `demo` (the sample layer, read
through three views). Setup is in `web/README.md` and `studio/README.md`.

## Where the pure layer ends

Everything under `src/lib/` and `scripts/` takes its inputs as arguments — fixtures, `today`,
`nowUtcIso`, the active filter set — and touches no DOM. That is what lets the node test
suite exercise the diff engine, the DST arithmetic, the heroes' planners and the URL codecs
on fabricated data, including the postponed, cancelled and in-play branches the real snapshot
almost never contains.

Components render what the pure layer decides. `useNow()` is the one place they read time;
`useUrlState` is the one place they read the URL. Every browser-found bug in this repo's
history — the `?date=` crash, the pinned-date rollover, the two heroes on two clocks — has
lived exactly on this seam, in the wiring between a hook and a component, which is why a
jsdom component-test rig is the next release and why "extract it to `lib/` and test it
there" is the standing review instruction.

## One skeleton, three lenses

The fixture list is one component tree. A **lens** (`?lens=`) may change four things:
atmosphere (default theme, lead accent), day-header scale, row density, and the hero at the
top of Fixtures — Ledger's Next-up strip, Poster's Tonight's slate, Broadcast's ticker.
Everything else is invariant, and the Table's markup is untouched by lens entirely. The lens
is applied twice by design: once by a classic inline head script compiled from
`src/themeBoot.ts` before stylesheets, and once in `App.tsx`'s effect for later switches.
Both use the same decoder and theme decision. An OS scheme change updates an unchosen theme;
an explicit choice takes priority, including in-session when storage is blocked.

Poster's hero and Ledger's hero share one gate, `stillToKickOff`, and one clock. That was the
v0.2.2 fix; before it, Poster filtered by status and Ledger by instant, and they contradicted
each other live once a minute on every match night.

## Two ESPN traps

1. **It caps responses at 100 events and does not say so.** A four-month range for La Liga
   silently returns the first 100 fixtures. The provider requests the window in 28-day chunks
   and refuses to write from any chunk that comes back at the cap.
2. **Some venue strings are wrong.** Two of Rayo Vallecano's twelve home fixtures in the
   current snapshot are tagged with Leganés's ground (Butarque); the other ten say Vallecas.
   Venue is cosmetic here and is not corrected by hand. A second provider that can disagree
   with the first is the durable fix — and an open invitation.

## The URL contract

Lens, tab, view, week anchor (`&date=`) and filters (`?only=`) live in the query string,
decoded by total functions: junk falls back to a default, never a crash. Two of those keys are
read by another repository — the betting pipeline's Step 0 uses `?only=` and `&date=` to pull
fixtures from a running instance — so a codec change there is a breaking change, not a
wording one.

## Commands

`npm run sync` writes to the repo, so read the conflict recipe below before you run it.

```bash
npm install
npm run dev              # dev server with hot reload at localhost:5173
npm test                 # vitest, two projects: node (tests/**/*.test.ts, minus tests/dom)
                         # and dom (tests/dom/**, jsdom)
npm run typecheck        # tsc -b --noEmit
npm run build            # static bundle in dist/
npm run build:single     # one self-contained dist-single/index.html, opens by double-click
npm run build:offline    # one self-contained dist-offline/index.html, Fixtures and Table only
npm run sync -- --check  # fetch and diff against the committed snapshot; write nothing
npm run sync             # refresh src/data/*.json; exits 1 when an urgent change is reported
```

`sync` takes `--from=YYYY-MM-DD` and `--to=YYYY-MM-DD`; the default window is −30 to +150
days. It needs no key and no account, because ESPN's scoreboard and standings endpoints are
public. You'll want Node 24 (24.15 or a later 24.x); 22.22.2 or a later 22.x, or any 26+, also
clear jsdom 30's engine floor (`^22.22.2 || ^24.15.0 || >=26.0.0`), mirrored in
`package.json`'s `engines`, which npm warns about rather than enforces. The fixture snapshot
is committed, so everything except `sync` works offline.

For a generated-data merge conflict, export the pre-merge branch's `fixtures.json` and
`standings.json` with `git show <commit>:src/data/<file>` into a temporary directory, then
use `npm run sync -- --baseline-dir=/absolute/path/to/that/directory`. The baseline preserves
first-seen rounds and notes and supplies the diff/shrink checks; it is schema-validated and
missing explicit baseline files fail closed. It changes input reads only: the three
conflict-marked files in `src/data/` are replaced exclusively by fresh, validated sync
output. Never use `--ours`/`--theirs` or hand-edit a generated file to resolve it.

The full-stack half has its own commands: `web/README.md` for the reader and the Vercel
preview, `studio/README.md` for the Studio. The standing brief for any agent working in the
repo is `CLAUDE.md`, which holds the verification discipline and the release rules.
