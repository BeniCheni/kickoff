## The approved boundary and its cost

**A fixture or standings fetch/validation failure aborts the sync with exit 2 before any
snapshot writes.** Fixtures and standings form v0.2.5's authoritative snapshot boundary;
metadata describes that same successful fetch. Fetch and validate both before publication.
If either fails, publish neither. Committed data remains the last completely successful
authoritative snapshot rather than a partially advanced state.

A standings outage can intentionally delay otherwise valid fixture updates. This is an
accepted availability cost of atomic publication of the fixtures + standings authoritative
snapshot, not an accidental side effect. Atomicity applies to this explicitly defined
boundary: future injuries, odds, weather, broadcast or other ancillary datasets do not
inherit membership automatically. Their semantics and failure consequences need a separate
decision. This supersedes the standings soft-failure exception introduced before v0.2.5.

The machine-readable report line keeps its existing shape. A refused fetch has exit 2 and
diagnostics, not a successful report; the workflow already treats that as a hard failure.
The `standings=failed` report variant remains accepted for compatibility with earlier runs.

## Audit and scope resolutions

All row numbers here name **`docs/v0.3.0-ideas.md`**; original descriptions also live in
`docs/v0.2.0-ideas.md`. The inherited spec is `docs/v0.2.4-proposal.md` and its review
resolutions. v0.2.5 stays one release, with the sync half first so its asynchronous dispatch
proof can run while the app half is built.

- **Row 8:** reject un-normalizable events and standings entries, with actionable context.
  Validate event identity before coercion and deduplication. An audit probe reproduced
  schema-valid `ligue1:undefined`; two id-less events per competition collapsed into one
  without a warning. A standings response with the expected valid row count plus a malformed
  extra entry was accepted too. Counts alone cannot account for rejected new entries.
- **Row 13d:** relocate `inWindow` under `scripts/`, derive its date with `brooklynDate`,
  test both inclusive edges under EDT and EST. The helper imports `src/lib/time.ts`; it does
  not live there. The app half's formatter changes may then edit `time.ts` without moving
  sync orchestration into the app layer.
- **Row 7:** stabilize codecs, retain fresh date defaults in popstate handling, preserve
  hashes, normalize owned URL keys on load. Unknown parameters survive. Existing total
  decoder semantics stay: uppercase `BROADCAST` is invalid and falls back to Poster.
  **`?date=<today>` unpins on load**, already decided. Two inherited rollover tests need a
  nondefault initial pin; keep their pin assertions and add coverage of today's unpinning.
  Period navigation's push/replace policy is not this release's work (row 9).
- **Row 6:** a class boundary keyed by `tab:lens` at the App seam, covering ticker, banner
  and page while keeping the header and navigation. Reload retries the URL; Reset view
  starts at the current pathname. Module-import snapshot validation happens before React
  mounts and cannot be recovered by this boundary. Event-handler and asynchronous errors
  are not promised recovery by a render boundary either.
- **Row 12:** generate a classic inline head bootstrap from the production lens/theme
  decision, test the generated output, and follow OS theme changes when there is no explicit
  choice. Broadcast keeps its separate memory and dark default. Extend the existing DOM rig.
- **Rows 13a and 13c:** move `posterDayTitle` into `time.ts`; expose structured clock and
  meridiem parts instead of parsing the formatter's currently guaranteed space.
- **Row 13b is already shipped:** `slateSubLine` and its mixed/all-TBC tests are present
  since v0.2.2. Only the remaining Poster day-header counterpart, **row 19**, is implemented:
  extract the sub-line to `lensSelectors.ts`, name its TBC count, preserve time exclusions.
- **Row 11, one third:** qualify NEXT's time when its Brooklyn date is not today. Marquee
  speed, reduced-motion controls, palette changes and stale-LIVE design remain outside scope.

## Evidence and accepted implementation details

**Label implementation (13a, 13c, 19, one third of 11):** `ZonedParts` exposes `clock` and
`meridiem` from `Intl.formatToParts`; both heroes consume them directly. Existing combined
time labels retain their output. `posterDayTitle` now lives in `time.ts` and formats its
month directly. The extracted `posterSubLine` names non-exact times with `N TBC` and retains
the existing bounds' postponed/cancelled exclusions. NEXT uses `Sun 6 Sep · 8:30 PM` for a
later Brooklyn date, including a later week; same-day output is unchanged. No marquee speed
or motion-control change. CONFIRMED: typecheck and 251 tests in 23 files passed, including
the Poster header's production component wiring and the original hero TBC assertions.

**Row 12 implementation:** Vite's existing build API compiles `src/themeBoot.ts` as a small
IIFE. A `transformIndexHtml` plugin injects it as a classic script at the start of head in
development, the normal build and the single-file build. The nested build explicitly disables
config loading; it adds no dependency and no second decision string. Node tests execute the
compiled code in fresh VM globals across 160 lens/storage/OS combinations and six hostile
storage cases, comparing with `resolveTheme`.

App subscribes to the OS scheme and removes its listener on cleanup. Stored choices win;
Broadcast stays dark by default. Explicit toggles are also remembered by lens family for the
current session, so blocked storage does not let an OS event undo the user's click. The rig
now exposes `setDark`, `setReducedMotion` and listener counts over stable MediaQueryLists.
CONFIRMED: 240 tests in 22 files, typecheck and both builds passed. The build's existing large
snapshot-bundle warning is retained; no code-splitting scope was added. Production browser
proof follows after the remaining app changes.

**Row 6 implementation:** `ViewBoundary` surrounds ticker, staleness banner and selected
page in App; its `tab:lens` key clears a failed view when either selection changes. It uses
existing surface/ink tokens and two recovery actions, without a new error pill or design
state. React's caught-error reporting is retained. Tests now use the production boundary,
retain the uncontained-throw control, and throw under App in all six lens/theme combinations,
with additional ticker/banner coverage and recovery through both navigation controls.
CONFIRMED: typecheck and 235 tests in 21 files passed. Browser recovery remains pending.

**Row 7 implementation:** `urlCodecs.ts` owns the tab/view/league/filter codecs alongside
`canonicalSearch`. Date callbacks are memoized by `today`; the popstate subscription is
keyed only by its URL key and delegates to `useEffectEvent` for fresh render values. App
normalizes all owned keys once per load, including inactive-page keys, preserving unknown
keys, history state and the hash. This deliberately re-encodes commas as `%2C` and collapses
duplicate owned keys to the first value the decoder read. It does not lowercase invalid lens
values or change history policy. A date that becomes today after arrival stays pinned.

The two original pin-regression assertions are retained: their setup now establishes the
same pin on the preceding day and wakes to its date before the original midnight steps.
A separate test proves that a date equal to today on arrival is omitted and follows midnight.
Other DOM tests cover stable setter/subscription identity, latest defaults/decoders, the
deployment pathname and hash, StrictMode cleanup and Step 0 after rollover. CONFIRMED after
row 7: typecheck and 227 tests in 20 files passed.

**Row 13d implementation:** `scripts/window.ts` owns `inWindow(fixture, from, to)`;
`sync.ts` uses it for both the previous snapshot's diff window and the shrink guard's
baseline. Ten edge cases cover EDT and EST, plus one window crossing the US fall transition.
The report formatter and pinned regex are unchanged. Branch dispatch evidence follows below.

**Row 8 implementation:** `runSync()` is the CLI's tested exit-code boundary. Both providers
reject un-normalizable entries, with competition, available identity, entry position and
reason; standings awaits all five results to retain all league diagnostics. Empty schedule
arrays remain valid, but a missing/non-array `events` field is a malformed fetch response.
Provider identity is checked before coercion/deduplication, with a schema backstop against
empty and coerced missing IDs. Missing time-confidence flags and score coercion are unchanged.

Both datasets and metadata are validated, then all three payloads serialized, before the
first write. Publication is the workflow's single Git commit of those files. This is not a
multi-file filesystem transaction: a disk/process failure during local writes can leave a
partial working tree, but a failed run is not committed. The fetch/validation failure
invariant is stronger: no snapshot write has begun. No new storage format or dependency.

Integration tests intercept filesystem writes while invoking the real orchestration: either
provider failing, either schema rejecting, waiting for standings, successful complete writes,
and `--check`. A subprocess also pins the actual CLI's exit 2 on an offline provider.
