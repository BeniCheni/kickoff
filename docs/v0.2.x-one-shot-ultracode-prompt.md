## 3. Adversarial review — fan-out, cold context

**The discipline that makes this legitimate:** each review agent receives the **diff, the
proposal, `CLAUDE.md`, and `docs/v0.3.0-ideas.md`'s Process-notes tail — and nothing else.** No
account of what you built, no explanation of why, no list of what you think is risky, no
reassurance that something was "already verified." If you catch yourself writing context into a
subagent prompt to save it time, that is the failure this phase exists to prevent.

A no-finding review of a real diff is a finding *about the review*.

### 3a — Dimensions, in parallel

One agent each, independent:

1. **Data honesty** — postponed/cancelled wearing a dead time; TBC leaking a confident number;
   anything invented (minutes, matchday numbers, scheduledness). The house religion.
2. **Time** — every `new Date()` / `todayIso()` capture; anything that freezes at mount; the clock
   store's subscribe/unsubscribe under StrictMode's double-subscribe.
3. **URL & history** — `useUrlState`, popstate, codec identity, push-vs-replace, junk params
   rendered-around but never normalized.
4. **Theme memory & contrast** — storage that throws; computed-style reads for every colour claim;
   a contrast check over every new pair in **both** themes.
5. **Motion budget & absolute words** — reduced-motion paths, and every "never" / "always" /
   "cannot" / "complete" in a comment or doc treated as a falsifiable assertion to test. Most of
   them have been false before.
6. **Scripts & workflows** — every `console.warn`-and-continue in `scripts/` (what would a reader
   who never sees the console want?), and any workflow branch you believe is reachable. **Read the
   previous run's log before believing a step is reachable** — the "Nothing changed" step was
   unreachable in shipped `sync.yml`, and only a real run's output proved it.

### 3b — Verify each finding independently, pipelined

As each dimension returns, fan its findings out one-agent-per-finding. Each verifier must
**reproduce the failure concretely** — a test, a command, a browser measurement — or mark it
**unreproducible**. Don't wait for all six dimensions before starting verification; a dimension's
findings verify while later dimensions are still reading.

Kill anything unreproducible. Report the kill; a rejected finding is information.

### 3c — Fix

Fix what's confirmed and in scope. Every behavioral fix gets a test where the logic is pure; if
logic sits inline in a component, extract it to `lib/` and test it there. No feature creep.

**Then compare §3's confirmed findings against your §2 scratch list** and report the delta in the
PR: what you flagged that the cold readers missed, and — the interesting half — what they found
that you didn't. That comparison is the actual experiment in this session.

### 3d — If release #1 contains `/beni-pr-review`

Then this phase is that skill's **first live test case**, exactly as
`docs/v0.2.1-pr-review-skill-plan.md` intends. Drive §3 through the skill rather than around it,

## 4. Verification matrix — scoped to what actually changed

**Full matrix** if the diff touches `src/` or `index.css`: every lens × theme × tab at **360, 375,
390 and ~1000px**. Set the viewport **before** any capture and assert
`document.documentElement.scrollWidth === window.innerWidth` on every screen. Batch the cells
across agents — they're independent. A pretty screenshot is a claim, not evidence.

**Smoke pass only** if the diff is docs/tooling: build, load, confirm no regression. Don't spend 48
captures proving a CHANGELOG edit didn't break the renderer.

Methods that already work here, so nobody re-derives them:

- **Driving the clock in a real browser:** inject a `Date` subclass carrying an offset through a
  `<script>` element (page world); `import()` the app's clock module by the exact URL Vite served
  it under (`performance.getEntriesByType('resource')`); check `subscriberCount() > 0` to prove
  you hold the app's instance and not a fresh one; set the offset; dispatch `focus` as the
  catch-up signal.
- **URL state:** `history.replaceState` + a synthetic `PopStateEvent` rather than navigating, so
  the shim survives.
- **The browser pane can be hidden while your script runs, and `requestAnimationFrame` never fires
  in a hidden document** — a rAF-based wait hangs to the tool timeout and looks like a stuck
  renderer. Settle React with `MessageChannel` ticks and measure with `scrollWidth`, which lays
  out on demand whether or not anything paints.
- **CSS transitions never advance while `visibilityState === 'hidden'`** — computed styles read
  mid-transition indefinitely, which looks exactly like a broken cascade. Flush with
  `document.getAnimations().forEach(a => a.finish())` (skip infinite animations), or measure on
  fresh loads.
- **390 is the judge, 360 is the jury.** The switcher wrap that "fit 390px" had zero pixels of
  slack and broke at ≤374px — including 360, the most common Android width.
- **Latent paths need synthetic data.** The snapshot holds zero postponed or cancelled fixtures,
  so no manual QA reaches those branches. Fabricated-fixture unit tests are their only coverage.
