# Kickoff v0.0.3 — Design Revamp: one instrument, three lenses (Claude Design prompt)

*Drafted 30 Aug 2026 from `docs/v0.0.2-proposal.md` §2 and the live repo (`src/index.css`,
`src/lib/competitions.ts`, the fixtures components). Paste the block below into Claude Design.*

---

## Context — read all of it before drawing

I'm building **Kickoff**, my personal Big-5 European football fixtures + standings tracker,
Brooklyn time (ET). I'm the only user; it opens on my Mac and, soon, my phone. It supports my
betting research, but you're not touching any betting logic — this is a pure visual design pass
on the **Fixtures** surface and the app shell around it. Stack, for your awareness only: React 19,
Tailwind 4 with CSS-variable tokens, a `data-theme` attribute for light/dark, URL-state filters.

### What v0.0.2 already settled (do not reopen)

- **The Table/Standings screen is finished and is the house-style reference.** Oswald caps for
  labels, IBM Plex Mono for numerals, Inter for body, hairline dividers, competition-color rails
  on zone rows, provenance callouts in floodlight amber, both themes token-driven. Do not
  redesign it. Every choice you make for Fixtures must sit next to it as *the same instrument*.
- **The persistent shell** — wordmark header ("KICKOFF" in Oswald 34px bold caps, "BROOKLYN · ET"
  in pitch green beneath, a tiny amber provenance line "v0.0.2 · 959 fixtures · synced 2026-08-30"),
  a theme toggle button top-right, then a tab row **Fixtures / Table** (Oswald caps on a 1.5px
  hairline, active tab in ink with a pitch-green `inset 0 -2.5px 0` underline). The shell stays
  on every screen and every lens.
- The v0.0.2 proposal offered three redesign directions for the Fixtures surface. I like **all
  three**. v0.0.3's idea is not to pick one.

### The v0.0.3 concept — one skeleton, three lenses

The three directions aren't three apps; they're three *readings* of the same fixture data at
different volumes. Design them as **lenses** — presets over one shared skeleton — that I toggle
between with a single control. The user-facing names:

| Lens | Origin | One-line character |
|---|---|---|
| **Ledger** | Direction A, Floodlit Ledger | The Table's language extended backwards: quiet, dense, a strong date spine, mono kickoff times, hairlines, marquee rails. The *default* lens. |
| **Poster** | Direction B, Matchday Poster | Editorial loudness confined to day headers and the day's hero: "SUN 30 AUG — 15 MATCHES · 5 LEAGUES" at poster scale, kickoff times set huge, competition color as duotone blocks. Rows underneath stay Ledger rows. |
| **Broadcast** | Direction C, Broadcast Deck | Dark-first stadium screen: floodlight amber promoted to primary accent, a live ticker strip across the top, soft glow on LIVE and next-up fixtures, mono-heavy. Light is still available — Broadcast just *defaults* to dark. |

**The cohesion rule that makes this one app instead of three:** a lens may change *only* these
four things — (1) atmosphere: which theme is default and which accent leads; (2) day-header
scale and treatment; (3) row density and the type scale inside a row; (4) the hero element at
the top of the Fixtures tab (Ledger: the compact "Next up" strip; Poster: tonight's slate as a
full-bleed hero; Broadcast: the live ticker strip). **Everything else is invariant across
lenses:** the shell, the tab row, the filter chips, the Weekly/Monthly control and period nav,
the two-clock rendering of every kickoff, provenance/staleness callouts, competition colors,
the Table screen, and the footer. If you find yourself wanting a lens to change something
outside those four axes, stop and flag it as a question instead.

Pleasantness and cohesiveness are the brief. Toggling lenses should feel like turning the
volume knob on one instrument, never like navigating to a different product.

**Current Fixtures-tab anatomy, top to bottom (this is the skeleton every lens shares):**

**What the audit said is wrong with it (your job is to fix these inside the lens system):**
every day is an identical-weight card so the Clásico and "No fixtures on August 25" take the same
space; rows are dense but flat — nothing says which match *matters*; the month grid's 5px dots
aren't data; the ticker's fixed 200px cards hide most of the slate; zero motion anywhere.

## The Lens switcher — spec

- **Placement:** in the shell, on the same visual line as the tab row, right-aligned — a
  three-segment control reading **LEDGER · POSTER · BROADCAST** in Oswald caps 11px. It must
  read as part of the shell (like the theme toggle), not as a Fixtures-page filter. On the Table
  tab it is present but visually quiet (the Table doesn't change with lens — show that state).
- **Form:** a segmented pill with a sliding thumb. Thumb color follows the lens's leading accent
  (pitch green for Ledger, ink for Poster, floodlight amber for Broadcast) so the control
  previews the atmosphere it's about to apply.
- **Motion:** thumb slides 180ms `cubic-bezier(.2,.7,.2,1)`; the page cross-fades tokens over
  220ms; day headers re-scale with a single ease, no bounce. Respect `prefers-reduced-motion`
  (cut to opacity only). Show the mid-transition frame once (artboard 4) so the implementer knows
  what "pleasant" means here.
- **Persistence / URL:** lens is URL state (`/?lens=poster`), default Ledger omitted from the
  URL. Theme is separate and persists independently — but **Broadcast sets dark as its default
  on first entry** and remembers if I flip it back to light. Design the theme toggle's label
  so it stays honest in all four combinations (lens × theme).
- **Keyboard/a11y:** it's a radiogroup; arrow keys move the thumb; focus ring in the lens accent.

## Per-lens specifications

### Ledger (default) — extend the Table's language backwards
- **Date spine:** a left column of big Oswald day numerals (28–32px) with the weekday in caps
  above, like a ledger margin; matches sit to the right as tight rows on hairlines, not inside
  cards. Today's numeral in pitch green with the "Today" pill.
- **Rows:** single-line-first — `HH:MM` Brooklyn time in Plex Mono leading the row, then
  "Home v Away", then a competition chip; venue, local time and TV drop to a second, muted line.
  Marquee fixtures get a 3px competition-color rail exactly like the Table's zone rails; LIVE
  rows get the accent pill; FT rows show the score in mono.
- **Empty days collapse to one hairline** with the day numeral dimmed and "—" in the row slot.
  A day hidden entirely by filters shows a single muted "3 hidden by filters" line.
- **Hero:** the "Next up" ticker becomes a compact horizontal strip of 4–5 narrow cards that
  actually fit a 390px viewport (no 200px fixed width), with "Today / Tomorrow / 3 days" in
  Oswald and the Brooklyn time in mono.
- **Month view (Ledger only, artboard 5):** replace dots with data. Each cell shows the match
  count and up to three competition-colored short bars; a marquee fixture gets a small ⭐ or a
  rail; tapping a cell reveals that day's Ledger rows beneath the grid. The grid must earn its
  place — if it can't, say so and propose the list-only alternative.
- **Motion:** 150ms ease on row expansion and the tab underline. Nothing else.

### Poster — editorial loudness, confined
- **Day header as poster:** "SUN 30 AUG" in Oswald 44–56px, a mono sub-line "15 MATCHES · 5 LEAGUES · FIRST KICKOFF 9:00 AM",
  and a duotone block behind it built from the day's dominant competition color over
  `--surface-alt` (two flat tones, no gradients). Days with ≤1 match get a small header, empty
  days stay a hairline — loudness must be proportional to the slate.
- **Rows stay Ledger rows** (same density, same anatomy). The only in-row change: kickoff time
  set larger (Plex Mono 20–24px) as the row's leading element.
- **Hero:** "Tonight's slate" replaces the ticker — a full-bleed block listing today's remaining
  fixtures with huge mono times and competition color bars; if today is empty, it shows the next
  matchday instead and says so.
- **Where it must stay quiet:** the shell, chips, controls, footer and Table are untouched.
  Poster shouts in headers only.

### Broadcast — dark-first stadium screen
- **Atmosphere:** dark tokens as default; floodlight amber (`#f7c948`) becomes the leading accent
  (tab underline, thumb, "Today" pill, focus rings) while pitch green recedes to secondary.
- **Ticker strip:** a single-line live strip pinned under the tab row — `LIVE  Man Utd 1–0 Ipswich 67'  ·  NEXT  3:30 PM Deportivo v Valencia  ·  …` — mono, amber
  keywords, gently auto-scrolling (pause on hover/touch, reduced-motion → static with a manual ›).
- **Glow:** LIVE rows and the next kickoff carry a soft amber outer glow (derive a
  `--glow` token from floodlight at ~18% alpha, 12–16px blur). Nothing else glows.
- **Rows:** Ledger anatomy, mono-heavier — team names in Inter, everything numeric in Plex Mono,
  slightly tighter leading. Day headers are Ledger-sized but with amber numerals.
- **Light variant:** must exist and must not look like a mistake — show it once (artboard 3c) so
  the token sheet proves both themes work under this lens.

## Rules, constraints, honesty

- **Table screen: untouched.** Reuse its elements; do not restyle them.
- **No new features.** No "what moved" panel, no Results tab, no betting/anchor overlays, no
  team pages. The tab row is exactly Fixtures / Table. (Leave visual room for a third tab — the
  reference's tab row had three — but don't draw it.)
- **Never invent data.** No matchday numbers (ESPN exposes none; the app refuses to guess).
  Every kickoff shows both clocks from one instant. TBC means TBC. Placeholder rows are
  captioned ILLUSTRATIVE.
- **Provenance posture is the house style:** "the data has a timestamp and a confidence." The
  amber provenance line, the staleness banner and the DATA footer survive every lens.
- **Both themes in every lens.** A lens chooses a default theme, never removes the other.
- **Contrast:** WCAG AA on body and mono text in every lens × theme; call out any pair that
  fails and how you resolved it.
- **Mobile first.** 390px is the primary judge; desktop is the second.
- **Copy stays terse and factual** — the existing voice ("Always verify in the book before
  staking.") is the voice.

## Handoff format — so the implementation prompt can be written straight from your output

Annotate, per lens, in a short notes panel on artboard 0:
1. **Token deltas** as `--token: light / dark` pairs that change under that lens (Broadcast will
   have several; Ledger should have none; Poster should have at most one or two).
2. **Component map** using the app's existing names — `TabNav`, `Ticker`, `FilterBar`,
   `WeekView`, `FixtureRow`, `MonthView`, `StalenessBanner`, `WatchPanel` — saying for each:
   unchanged / restyled / replaced-under-this-lens, and by what.
3. **Type scale table** per lens: day numeral, row time, team names, meta line (px + font).
4. **Motion table:** element, trigger, duration, easing, reduced-motion fallback.
5. **Open questions** — anything where you chose between two defensible options; I'd rather
   answer a question than discover a silent decision in the implementation.

## Before you start

If any of the following is unclear, ask before drawing rather than assuming: the switcher's
placement relative to the tab row on 390px (it may need to drop to a second line — show me
the option), whether Poster's duotone should key off the *dominant* competition of the day
or the *marquee* one when both exist, and whether Broadcast's ticker strip should also appear
on the Table tab (my instinct: no — the Table doesn't change with lens — but say if you
disagree and why).
