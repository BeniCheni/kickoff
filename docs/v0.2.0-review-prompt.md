## Review method — verify, don't vibe

**Static pass.** Read every new/changed file completely. Hunt these classes specifically:

- **Data honesty** — the house religion. Can the sync now write anything it doesn't
  understand? Trace `normalizeEvent` → `fetchWindow` → `sync.ts` for every exit path: is
  there any route to a write after an `UnmappedStatusError`, a cap hit, or a shrink trip?
  Does `--check` share every guard? Can the shrink guard misfire on a legitimate shrink (a
  cup rolling out of the window, a winter break, the rolling window's edge)?
- **Time** — `src/lib/clock.ts` and every `useNow()` consumer. Minute alignment, the re-arm
  after each tick, the settle margin, the `focus`/`visibilitychange`/`pageshow` catch-up,
  refcounted start/stop, StrictMode's double subscribe, the stable snapshot identity. What
  happens across a DST transition, a clock set backwards, a tab throttled to one timer a
  minute, a `visibilitychange` that fires while hidden? Is `nowUtcIso` at millisecond
  precision a problem anywhere a minute-floored value was assumed?
- **The re-anchor effect** in `FixturesPage.tsx`: the URL is the pin test. Enumerate the
  cases — no `?date=`, `?date=<yesterday>`, `?date=<today>`, "Jump to today", Back/Forward
  across a rollover, the month view anchored to the 1st.
- **The workflow** — `sync.yml` line by line: exit-code capture under `-eo pipefail`, the
  `dry_run` input arriving as a string, `concurrency`, the force-push to `sync/scheduled`,
  the `gh pr list`/`edit`/`create` branch, the dispatched `verify` check, what a standings
  failure (non-fatal by design) looks like in the PR body, and what the first cron run will
  do the moment this merges. Permissions: is `actions: write` the minimum? Is anything in the
  body user-controlled text GitHub would render as markdown?
- **Absolute words in comments** ("never", "always", "cannot", "exactly") — each is an
  assertion to test.
- **Tests** — do the new ones test behavior or implementation? Is any data-honesty assertion
  weaker than before? Are the synthetic events honest stand-ins for ESPN's shape?

**Dynamic pass — mandatory, in a real browser.** Build, serve, and drive it: all 3 lenses ×
2 themes × 2 tabs at **360, 375, 390 and ~1000px**; set the viewport *before* any capture and
assert `document.documentElement.scrollWidth === window.innerWidth` on every screen. Re-run
the row-1 clock scenarios yourself — do not trust the PR body's account of them. The method
that worked last time: inject a `Date` subclass carrying an offset into the page through a
`<script>` element (so it runs in the page's world), import the app's clock module by the
exact URL Vite served it under (`performance.getEntriesByType('resource')` shows the `?t=`
suffix — a plain import gets a fresh, unsubscribed instance), and dispatch a `focus` event as
the catch-up signal. Also drive `sync.yml` once yourself:
`gh workflow run sync.yml --ref claude/kickoff-v0.2.0-time -f dry_run=true`, then read the
step log. A real (non-dry) dispatch against the branch opens a PR that inherits the whole
tree and shows CONFLICTING — expected; close it and say so.

## Fix policy

- Fix what you can **verify** (reproduce or demonstrate), in scope: correctness, honesty, the
  workflow's failure paths, layout defects, small structural cleanups the fix naturally
  touches. Every behavioral fix gets a test where the logic is pure.
- No feature creep: no auto-merge, no jsdom rig, no stale-LIVE pill design, no new
  dependencies (runtime or Actions), no Table restyling, no token repaints. If a real fix
  requires an out-of-scope file, stop and say so.
- Never weaken a data-honesty assertion to make anything pass.
- Commit in small reviewable units, each message saying what was broken, how you proved it,
  and how the fix was verified. **Author commits as `Claude <noreply@anthropic.com>`** via a
  per-commit `git -c user.name=Claude -c user.email=noreply@anthropic.com` (never
  `git config` — the repo config is shared across worktrees), with the trailer
  `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Appendix — leads from the completing session (verify independently; trust nothing)

The session that completed the branch noted these while reading and verifying. Re-derive
each yourself before acting — if one doesn't reproduce, say so rather than fixing ghosts:

- `clock.ts`'s `notifyIfChanged` compares full-millisecond `nowUtcIso` strings, so a `focus`
  event a few seconds after a timer tick *does* notify and re-render, despite the comment
  saying a same-minute visibility tick is a no-op. Harmless in practice (one re-render per
  focus), but the comment and the behavior disagree; decide which is right — a minute-floored
  snapshot would make "the clock ticks in minutes" literally true.
- `FixturesPage`'s re-anchor effect lists `setAnchor` in its dependencies, and `useUrlState`'s
  `set` identity changes every render (roadmap row 7), so the effect body runs every render
  and relies on the `prevToday` ref to no-op. Correct, but fragile; row 7's fix would make it
  clean.
- `TonightSlate` (Poster) keeps a `scheduled` fixture in "N REMAINING" after its exact
  kickoff has passed — it never reads `nowUtcIso`; Ledger's Next-up drops it. Pre-existing and
  out of scope, but the two heroes now disagree *live*, once a minute.
- `sync.yml`'s "Nothing changed" step is unreachable in practice: every run rewrites 959
  `fetchedAt` stamps. Is that the right design, or should the workflow read the diff engine's
  report to decide whether a PR is worth a human's time?
- `implausibleShrink` runs on `counts` from `fetchWindow` (everything fetched, pre-validation)
  against `previousInWindow` — a chunk of schema-invalid rows would pass the shrink guard and
  then be dropped by validation with only a `console.warn`. Is that a third silent path?
- The placeholder `sync.yml` on `main` (`b314037`) has `workflow_dispatch` only; this PR
  replaces it. Confirm the merge leaves exactly one `sync.yml`, with the `schedule:` trigger.
- The inherited commits' own verification claims ("browser verification deferred to the end")
  were made good by the completing session's pass; the PR body lists what ran. Re-run, don't
  re-read.
