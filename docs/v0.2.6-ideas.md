## Process notes

Read **all** the process-note tails in `docs/v0.3.0-ideas.md` and
`docs/v0.2.0-ideas.md` as well; this file adds method instead of replacing it.

- **Define the authoritative snapshot boundary before promising atomicity.** Fetch and
  validate every member before any write. Here the members are fixtures + standings;
  metadata describes that snapshot. The Git commit publishes them together. This is not a
  multi-file filesystem transaction, and future ancillary datasets need a separate membership
  decision. Test failure before writes by invoking the real orchestrator with intercepted IO;
  also pin the actual CLI's exit code in a subprocess.
- **Expected counts do not excuse a rejected entry.** Add a malformed extra entry to an
  otherwise complete standings table. A minimum-count-only test cannot see that loss.
  Validate identity before coercion and deduplication; otherwise two missing identities can
  collapse before the schema sees either one. Diagnostics need the available identity and
  context, not a reconstructed one.
- **A generated bootstrap needs two proofs.** Execute the compiled output against the shared
  decision across storage/OS/lens combinations, then serve `dist/` and hold the application
  module at the network layer. Inspect root attributes and computed background while React's
  root is empty, release the module and compare again. A dev-server load does not establish
  production ordering. Reuse the existing build dependency; avoid a second hand-maintained
  decision string.
- **An error boundary's claim must name its seam.** Inject a throw into a served component
  response in an isolated browser, without changing snapshots or shipping a crash switch.
  Check tab and lens remounts, Reload's actual navigation, and Reset view's cleared URL in
  all six lens/theme combinations. A module-import validation error before React mounts is
  outside this boundary. Assert against the real markup: this Table uses divs, not `<table>`.
- **A pin regression must start from a nondefault pin.** Once the product normalizes
  `?date=<today>` away on arrival, that URL cannot establish the old test's persistent pin.
  Start on the preceding day, then tick through the pinned day and the following midnight.
  Keep the pin assertions; separately prove today's unpinning and a Sunday-to-Monday follow.
- **Browser assertions need the running app's values.** Read competition keys instead of
  guessing an abbreviation. Import the exact served clock URL and verify positive subscriber
  count before driving focus catch-up. Keep viewport-before-capture and width assertions on
  auxiliary captures too. Inspect the whole matrix, then scroll to changed content hidden
  below a long hero; the first viewport does not prove a day-header sub-line.
- **Run the asynchronous proof early, then record its exact head.** A successful branch dry
  run proves that tree and the unchanged report regex. App edits to an imported time module
  justify another dry run on the final code. Documentation receipts can follow without
  amending away the SHA. Required PR checks still need the PR's own event run.
- **Keep transient QA evidence outside the source tree.** An isolated Chrome profile, native
  CDP driver and machine-readable case receipts can exercise the matrix without adding
  Playwright or a second permanent rig. Retain the captures for the handoff, distinguish local
  artifacts from GitHub-visible evidence, and put the reproducible conditions in the proposal.

Added by the v0.2.5 review (PR #23, 5 Sep 2026):

- **`matchMedia` change events need a rendering opportunity.** They dispatch in the "update
  the rendering" steps, which a hidden document can defer: the pane's emulated
  `prefers-color-scheme` flip read `matches: true` while the app's listener had not run, and
  looked like a broken listener. Force a frame (a screenshot does it) before reading the DOM.
- **Derive every clock-shim jump from the real clock, not from `Date.now()` after the shim is
  installed.** A second `__setOffset(target − Date.now())` compounds the first offset; capture
  `realNow` before the shim goes in. The compounded run drove Sep 5 → 6 → 12 → 7 and still
  "passed" every assertion, which is the tell: a probe whose intermediate dates you never
  print can pass for the wrong reason.
- **An uncommitted, hash-gated throw is one boundary probe.** One line in a served
  component (`if (location.hash === '#boom') throw`), scoped to one tab so the other
  recovers, covers six lens × theme cells at two widths, Reload and Reset view. Restore
  only the probe from a saved copy, preserving any pre-existing edits; the review used
  `git checkout` on its otherwise clean file. Read React's
  caught-error report in the console to confirm the boundary named itself.
- **The pane refuses `file://`.** A single-file build's "opens from the filesystem" claim
  cannot be checked there. An HTTP preview proves served loading, not filesystem loading;
  use a browser that permits `file://` or a human double-click for the latter. Pass 2
  verified both with isolated Chrome and the repository's existing `npm run preview` script.
- **When a doctrine retires a report value, grep the method too.** `standings=failed` is
  unreachable since v0.2.5, yet `CLAUDE.md`'s hold-reason list and
  `.claude/skills/kickoff-pr-review/SKILL.md` §0 still recite "a failed standings fetch" as a
  live hold. Left as they are by this review (the skill is not this PR's tooling); the next
  patch that touches the skill should reword both. The `--check` form the skill allows still
  works under the new entry-point guard, and now returns through `process.exitCode` (exit 1
  with a report line on 5 Sep).
- **Retro on the skill, counted.** Right: viewport before capture, the MessageChannel settle,
  the clock-shim recipe, the one-comment shape, and "re-run what the proposal promised" — the
  proposal's own table was the checklist. The held production-module load and filesystem
  opening were exceptions, as the review comment records; Pass 2 supplied those proofs. Wrong or
  missing: the three notes above (MQL frames, `file://`, the retired hold reason), and no
  line on how to smoke a *built* app in the pane when the diff changes what only a build shows
  (here, head order). A charset budget the build could silently cross was the one finding the
  build's own 48-cell matrix could not see; a byte-order read of `dist/index.html` should join
  the smoke pass whenever `transformIndexHtml` or `index.html` changes.

Added by the PR #24 review (5 Sep 2026):

- **A badge or credit line is a claim too.** A one-line README diff adding a "built with X"
  badge looked trivial until it was checked against `CLAUDE.md`'s stated build process and
  didn't match — the fix wasn't code, it was asking the human whether the claim was current
  rather than guessing (it was: the SDLC had genuinely grown a second builder, README just
  hadn't caught up). Treat provenance/credit claims with the same "verify, don't vibe"
  standard as a data-honesty assertion, and escalate rather than silently editing or silently
  merging when a new claim and the repo's own docs disagree.
- **A PR body is a claim about its own diff, and can be wrong too.** This PR's body said it
  would "replace" a badge; the diff only ever added one. Read the two side by side before
  trusting either — `gh pr edit` is cheap once the mismatch is found.

Added by the PR #26 review (Pass 1 of the cross-vendor 360, Claude Code, 6 Sep 2026):

- **A headless CDP driver (Node 24's global `WebSocket`, no dependency) is what reaches
  `prefers-reduced-motion`.** The pane cannot emulate it; `Emulation.setEmulatedMedia` can,
  and `matches` read true only after a forced frame — the v0.2.5 note held. Three driver
  traps cost a run each: `Runtime.evaluate` returning a DOM node by value fails with "Object
  reference chain is too long" (end the expression with `; true`); `await import()` needs an
  async wrapper, so cache the app's module on `window` once; a hover dispatched at page
  coordinates below the fold never fires — `scrollIntoView` first, viewport coordinates for
  input, page coordinates for a screenshot clip.
- **A derived field is not in the JSON.** Standings rows carry `gf`/`ga`, not `gd`; a query
  on `r.gd < 0` said "no negative rows" and was wrong — Racing Santander sits at −1 in the
  rendered table. Check a claim about a computed value against the renderer (or `tableFor`),
  never the raw file.
- **An in-memory fixture edit renders only when the consuming memo's dependency moves.**
  `WeekView`/`MonthView` key on the minute (`nowUtcIso`); `TablePage`'s rows on `today`.
  Mutate, then jump across a minute (or a day) and dispatch `focus`; a same-minute catch-up is
  a no-op by design and looks like a mutation that did not take.
- **Tailwind v4 opacity modifiers are oklab `color-mix`, and the rendered pixel is the
  ground.** Chrome reports `bg-accent/10` as `oklab(… / 0.1)`; the composited pixel differed
  from the sRGB prediction by one channel unit (72h banner: 4.53 measured, 4.55 predicted).
  Under a 0.05 margin, sample the pixel — `Page.captureScreenshot` with a 1×1 clip decodes
  with `zlib` alone — rather than trusting either computation.
- **A clock shim whose `__setTarget(ms)` subtracts the real `Date` captured inside its own
  closure cannot compound.** Every receipt prints `now`, `real` and the offset per jump; a
  probe whose intermediate dates you never print can pass for the wrong reason (the v0.2.5
  note, kept).
- **Retro on the skill, counted.** Right: "latent paths need synthetic data" and the
  boundary framing (−1 ms, 0, +1 ms, one constant, the complement, the stored status) were the
  review's method; the sealed-appendix discipline surfaced two spec deviations the appendix had
  guessed at and one sub-claim it overstated (KICKED OFF and POSTPONED differ by label, not
  hue alone). Wrong or missing: §4 has no line on reaching a `prefers-reduced-motion` state
  (above), none on sampling a rendered pixel when a contrast margin is thin (above), and §3's
  Theme class asks for computed-style reads without asking which *ground* the test asserts
  against versus the one the component renders on — the Table hover and the banner tints were
  that gap, and this PR closed it by inventory; the line to add is "list the grounds by
  component before trusting a contrast table". The skill's own §0 edit in this PR is accurate
  against `scripts/` as they stand, and a review that reads its own instructions should say so
  in its comment.
