THE RULE TO IMPLEMENT. In `decideRequest` the `shelf` expression keeps every existing condition (resource type `image`, no body, path `/vi/`, `/vi_webp/`, `/an_webp/` or `/sb/` followed by one segment and a further `/`, exactly one extracted id) and replaces `!u.search` with a query check that accepts either an empty query or a query that satisfies all of: every key is exactly `sqp` or `rs` (case-sensitive); each key appears at most once; every value is non-empty, at most 256 characters, and consists only of letters, digits, `_`, `.`, `-`, `=`, `+`, `/` and percent-escapes of the form `%XX`; and `extractIds` still returns exactly one id for the whole URL. Anything else in the query, any other key (including `v`, `video_id`, `docid` and any key not listed), a repeated key, an empty or oversized value, a value that is or contains a nested URL, or a second extracted id, keeps stopping with `unnamed-id`, exactly as today. Write the check as a small named function in policy.ts so a mutant can target it. Nothing else changes: a frame, document, API, fetch, XHR or media request that names an unnamed id still stops; a named id with any query is unchanged; the host, scheme, port and userinfo checks that follow still apply; and the redirect guard is untouched. Record the decision under the existing reason `shelf-image`, with the extracted id in the receipt as now.
