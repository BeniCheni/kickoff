# Kickoff v0.0.2 — Audit, Redesign Directions, DX & AI Findings, Hosting Plan

*Session date: 2026-08-29. Everything below is grounded in the repo and the running app —
package.json, the component tree, the decoded `Kickoff Standings.html` artboards, live ESPN
API responses, and click-throughs at :4173 (built) and :5173 (dev).*

---

## 1. Audit — what's here now

**The good, and it's genuinely good:** the data layer is the most distinctive thing about
this app. One UTC instant per fixture with both clocks derived, provider flags honoured
("time not yet set" instead of a confident lie), every sync diffed with urgency exit codes,
the snapshot committed as an audit trail. The hand-tuned "floodlit pitch" palette with full
dark mode is better than most production apps. URL-state filters that survive reload. This
posture — *the data has a timestamp and a confidence* — is the house style, and the
standings design reference correctly treats it as such.

**What was wrong or missing (per screen, as actually seen):**

- **Navigation: there was none.** The standings view didn't exist at all — not a hidden
  route, simply never built. The whole app was one fixtures page. *(Fixed this session —
  see §6.)*
- **Fixtures week view — vertical monotony.** Every day is an identical-weight card;
  a day with the Clásico and a day with "No fixtures on August 25" occupy the same visual
  space. Scanning a week is reading, not glancing. Fixture rows are information-dense
  (two clocks, venue, TV, status) but flat — nothing tells you which match *matters*
  beyond a thin left border for non-domestic competitions.
- **Month view — dots aren't data.** 5px competition dots in aspect-square cells: you can
  see *that* something happens, not *what*. The month grid then repeats everything below
  as a list, so the grid is decoration. The list is the real month view.
- **Ticker** — the best-looking element on the page (color, hierarchy, "Today/Tomorrow"
  headline), but fixed 200px cards in an overflow scroll hide most of the slate.
- **Zero motion.** No transitions anywhere — tab switches, expansions, theme toggle all
  hard-cut. For a "fun to open" bar, this is the cheapest missing ingredient.
- **Research jobs unsupported:** nothing surfaces "what moved in the last sync" inside the
  app (the diff prints to a terminal and is gone), nothing flags time-TBC fixtures inside
  the staking horizon, no join to positions/tokens (envisioned in the README, not built).
- **Micro-nits:** header version string is hardcoded (`v0.0.1`) rather than read from
  package.json; no favicon; the served :4173 build can silently lag the source (it did —
  it was 5 days ahead of the worktree's data and behind its code).

## 2. Redesign directions

The Table reference settles the house style wherever it overlaps: Oswald caps for labels,
IBM Plex Mono for numerals (now loaded app-wide), hairline dividers, competition-color
rails, provenance callouts in floodlight amber, both themes token-driven. All three
directions keep the persistent header + tab row exactly as shipped; they differ in what the
*fixtures* surface becomes.

### A. Floodlit Ledger — extend the Table's language backwards *(recommended)*
The fixtures list becomes a ledger the way the table already is one: strong date spine on
the left (big Oswald day numerals), matches as tight rows with mono kickoff times, marquee
fixtures get a competition-color rail exactly like zone rails, empty days collapse to a
single hairline. Motion: 150ms ease on expansion/tab underline, nothing else.
**Rationale:** the reference *is* this direction applied to standings; the app becomes one
coherent instrument. Lowest risk, highest coherence. **Fit with reference: perfect** — it's
the same design extended.

### B. Matchday Poster — editorial loudness on the fixtures screen
Each day opens with a poster-scale header ("SAT 30 AUG — 11 MATCHES · 3 LEAGUES"),
kickoff times set huge in mono, competition color used in duotone blocks rather than
chips; "tonight's slate" replaces the ticker as a full-bleed hero. **Rationale:** maximum
"fun to open"; every matchday feels like an event. **Fit with reference: partial clash** —
the Table stays quiet while Fixtures shouts. Reconcilable because they're different screens
sharing one shell, but the app stops feeling like one instrument. If you pick this, the
shared shell (header, tabs, callouts) stays reference-styled and the poster treatment is
confined to day headers.

### C. Broadcast Deck — dark-first stadium screen
Dark green becomes the default (light the alternate), floodlight amber promoted to the
primary accent, a live ticker strip across the top, subtle glow on live/next fixtures,
mono-heavy throughout. **Rationale:** matches the evening/night rhythm of actually watching
European football from Brooklyn; the dark tokens are already the better-looking theme.
**Fit with reference: flagged clash** — the artboards present light-cream as the default
state (1a) with dark as a state (1b). Dark-first inverts that hierarchy. The tokens all
exist so nothing breaks, but if the cream default matters to you, don't pick C.

## 3. Feature ideas (ranked by daily-research value)

**Shipped this session** (from the design artifact's embedded ideas — these were cheap):
qualification-zone legend with per-league tie-break rules · games-in-hand callout + `+1`
chips + PPG column · per-row expansion · data-freshness line · desktop sortable columns
with canonical-Pos banner.

**Cheap next (order of value):**
1. **"What moved" surface** — sync already computes the diff; write `changes.json` alongside
   the snapshot and render the last sync's moves + all time-TBC fixtures inside 7 days as a
   collapsible panel. This is the app's core promise made visible in the app itself.
2. **Results tab** — the reference's third tab. Last-7-days scores by league; data is
   already in the snapshot (`result` on full-time fixtures). Completes the tab row.
3. **PWA manifest + favicon** — makes the phone URL feel native once hosted; an afternoon.
4. **Version string from package.json** — `define` in vite.config, delete the hardcoded one.

**Structural (defer, but the seams exist):**
5. **Anchors overlay** — join `positions.json` / `tokens.json` on fixture id (the id design
   anticipates exactly this); badge fixtures carrying an open position or a token expiring
   before kickoff. Highest research value of anything on this list, but it needs the
   betting-side files defined first.
6. **Home/away split table** — the reference's Overall/Home/Away control. ESPN's standings
   feed has no venue split, so it must be computed from full-season results, which requires
   retaining results back to matchday 1 (the sync window slides past them by November).
   Needs a "keep season results" rule in the sync — a deliberate pipeline change.
7. **Team detail view** — the reference's "Team detail →" button target.

## 4. Stack & DX findings

**Verdict: the stack is current — no upgrades needed.** React 19.2, Vite 8, Tailwind 4
(CSS-first `@theme`), TypeScript 7, Vitest 4, Zod 4, tsx. Nothing on this list has a
meaningfully newer generation as of Aug 2026. The absence of a router, state library, or
component kit is correct at this size — resist adding them; `useUrlState` is the router
and it deep-links better than most routers do.

Worth doing for pleasure-of-tinkering, all small: wire the real version into the header;
a `check` script (`typecheck && test`) as the pre-commit habit; favicon; the `changes.json`
idea above (it also makes future features honest). `.claude/launch.json` was added this
session so any future session can run the app in the preview pane immediately.

## 5. AI features against free tiers (verified Aug 2026)

Free-tier landscape, checked this session: **Gemini API** free tier ~10–15 RPM on Flash
(cut from 2025 levels, still ample for one user); **Groq** ~30 RPM / 1k req-day free on
Llama-class models, fastest inference; **OpenRouter** ~50 free-model requests/day (1k/day
after a one-time $10 credit purchase); **Cloudflare Workers AI** 10k neurons/day;
**Ollama** local — free forever, an M-series Mac runs 8B-class models and embedding models
comfortably.

Ranked — **(a)** = actually helps research/enjoyment, **(b)** = technically impressive:

1. **(a) Sync-diff note drafter.** When sync flags a move inside 72h, one Groq/Gemini call
   drafts the fixture `note` ("moved from Sat to Sun after UCL draw — check moneyline
   direction"), you approve/edit. Tiny build, touches the exact workflow that exists.
2. **(a) RAG over your research history** — your instinct is right and this is the
   plausible "yes". Local embeddings (Ollama `nomic-embed-text`) over `../Sportsbooks/`
   notes, retrieved-by-fixture and shown in the row expansion. No cloud dependency, no
   rate limits, private by construction. Medium build; do it after the corpus is worth
   querying.
3. **(a/b) Pre-match brief button** — compose fixture + table context (both already in the
   snapshot) into one Gemini call with search grounding for team news. Useful, but
   honesty: without grounding it's a knowledge-cutoff hallucination risk dressed as
   research; with grounding the free quota is limited. Build it as "context assembly +
   one call", never as an oracle.
4. **(b) Natural-language fixture queries** ("Sunday games before noon") — the filters
   already answer these in two taps. Fun, not valuable.
5. **(b) Fine-tuning/training anything: no.** Data volume, cost, and payoff all argue
   against; nothing in this app needs a custom model. You said this yourself — you're not
   wrong.

## 6. Shipped this session — Fixtures ↔ Table navigation + full Table

- **Routes:** `/` = Fixtures · `/?tab=table` = Table (deep-linkable, e.g.
  `/?tab=table&league=pl`). League picker state is in the URL too.
- Persistent tab row on both pages, matching the reference exactly: Oswald caps, hairline
  base, active tab in ink with the pitch-green `inset 0 -2.5px 0` underline.
- Full Table view: official standings synced from ESPN's public standings API by
  `npm run sync` into committed `src/data/standings.json` (same generated-and-diffed
  posture; rank moves logged, never driving the exit code). Zones, legend, tie-break
  copy, PPG, games-in-hand, form pips and next-fixture join, mobile row expansion,
  desktop sortable columns. All five leagues.
- Verified in the running app both directions, both themes, 390px and desktop; tests
  (32) and typecheck green.

**Deviations from `Kickoff Standings.html`, and why:**
1. **Tabs are Fixtures / Table** — no Results view exists yet, so per the brief the
   Results tab is noted as future rather than invented.
2. **Home/away split control absent** — deferred (see §3.6; the feed has no split).
3. **"Team detail →" / "All fixtures →" buttons omitted** — they'd be dead links; they
   arrive with the team-detail view.
4. **"As of matchday N of M" is computed** (most-played club vs. a double round-robin),
   not an official round number — ESPN exposes none and the README's own rule forbids
   inventing one. The artboard's "matchday 2 of 38" was a laliga.com placeholder.
5. **Movement arrows use the feed's `rankChange`** — currently mostly "–" this early in
   the season, where the artboard showed illustrative ▲▼.
6. **Underline is pitch green** per the artboards (the brief's "accent color" recollection
   would have made it orange; the reference wins).
7. Live data replaces the artboard's sample kickoff times and form strings — the artifact
   itself asked for exactly this (`pending npm run sync`).

## 7. Hosting & deployment plan

**Recommendation: Cloudflare Pages.** Free tier has unlimited bandwidth (the only one of
the four majors without a 100GB cap), 500 builds/month, direct GitHub integration. This
app is a fully static bundle (data baked in at build), so nothing else is needed — no
functions, no database.

**Runner-up: GitHub Pages** — the repo already lives at `github.com/BeniCheni/kickoff`;
an Actions workflow builds and publishes. Requires the repo to be public on the free plan
(Cloudflare doesn't care). Both are equally fine at this scale; Cloudflare wins on not
needing the repo public and on bandwidth headroom.

**Pipeline (hand this to a future session):**
1. Connect the GitHub repo in the Cloudflare dashboard → Pages → build command
   `npm run build`, output `dist`. Every `git push` to `main` deploys. Vite's
   `base: './'` already makes the bundle path-agnostic.
2. **Freshness without the laptop:** a scheduled GitHub Action (e.g. every 6h) runs
   `npm run sync`; if the data changed, it commits `src/data/*` — which triggers a
   deploy. The sync's exit-1-on-urgent-move becomes a workflow signal: have the action
   open a GitHub issue titled with the diff summary instead of failing silently. The
   phone always shows fresh fixtures *and* the audit trail stays in git, exactly the
   house philosophy, now self-driving.
3. No SPA fallback config needed — routing is query-params only, so `/` is the only path.
4. Later, optional: `manifest.json` + icons → installable PWA on the phone home screen.
