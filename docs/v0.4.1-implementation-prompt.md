R44 — results compared by role. scripts/diff.ts:137-143 compares before.result.home with after.result.home even when isInversion(before, after) is true, so a role correction with unchanged per-team goals (Alpha 2–1 Beta, then Beta 1–2 Alpha) emits an urgent RESULT\_CHANGED "2-1 -> 1-2". The rule: when inverted, the result is unchanged if and only if after.result.home === before.result.away and after.result.away === before.result.home. Otherwise emit RESULT\_CHANGED with a per-team detail, e.g. "Alpha 2 -> 3, Beta 1 -> 1". Non-inverted fixtures keep today's comparison and detail. Tests: a same-score inversion gives HOME\_AWAY\_INVERTED only; an inversion with a real correction gives both; existing cases are unchanged. Do not touch RANK.

R48 — a red run must say which half failed. Since v0.4.0 a run can end red after its data shipped, and ../Sportsbooks/CLAUDE.md treats any red run on main as "re-verify every open position". Acceptance: from \`gh run view \<run-id>\` alone, a reader sees exactly one of three outcomes, and the run summary repeats it in one sentence:
\- DATA FAILED — nothing was published (fetch, validation, verify, digest, commit or PR creation failed).
\- MERGE UNCONFIRMED — snapshot PR #N exists but was not seen merged (closed, head moved, or still open after ten minutes); when the merge step warned that auto-merge was refused, say auto-merge may be off.
\- DELIVERY FAILED — the snapshot is on main at \<sha> but the Pages request failed, so main is current and the live site may lag.
Default design (use it unless a smaller one meets the acceptance):
\- finish-sync.sh gets \`id: deliver\` and, before every exit, writes \`delivery=merged|merge\_unconfirmed|delivery\_failed\` and a one-sentence \`delivery\_detail\` to $GITHUB\_OUTPUT.
\- ensure-pages.sh wraps \`gh workflow run\` so a rejected dispatch prints an error (today \`set -e\` exits silently). When it runs inside the "Recover Pages delivery of an earlier merge" step (continue-on-error), an env flag makes it print a ::warning about the earlier merge instead.
\- A new last step, "Classify a red run" (\`if: failure() && steps.mode.outputs.dry\_run == 'false'\`), takes the outcome from steps.deliver.outputs.delivery. With no delivery output it reports MERGE UNCONFIRMED if steps.pr.outputs.number is set, and DATA FAILED otherwise. It emits one \`::error title=\<OUTCOME>::\<OUTCOME> — \<detail>\` (start the message itself with the outcome word, since the title is not always displayed) and writes the same sentence to $GITHUB\_STEP\_SUMMARY.
Every outcome stays red; v0.4.0's "fails visibly" holds. Test finish-sync.sh's outputs and exit codes in the existing gh-mock rig, and test the classifier by extracting its shell with substituted outcomes. Do not edit ../Sportsbooks; put the three exact strings in the PR body for the PM seat.
