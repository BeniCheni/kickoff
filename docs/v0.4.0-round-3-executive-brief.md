## What ships

- **The header stamp stops lying by omission through a break.** Before this release, a quiet
  scheduled check verified nothing had moved and then published nothing. The latest main run,
  [34545673861](https://github.com/BeniCheni/kickoff/actions/runs/34545673861), skipped its commit
  and PR for exactly that reason. Quiet checks now publish a `sync: verified unchanged` snapshot
  through the same required `verify`.
- **Corrections become visible.** The diff engine now reports `RESULT_CHANGED` (two known scores
  differ), `TEAM_CHANGED` (provider identity changed) and `TEAM_RENAMED` (same identity, new name,
  once per competition). Corrections are urgent at any horizon inside the 30-day look-back;
  renames never are.
- **Bot merges finally reach the live site.** Bot-token merges don't fire `push` workflows. Since
  PR #28, 0 of 7 bot-merged sync PRs (#31, #32, #35–#38, #40) got a Pages run; the site
  still serves `eccad28`, not the `782613b` snapshot. The sync now watches its own merge and
  dispatches `pages.yml`. The next real run retries a missed deploy.
- **A change digest lives on main.** `docs/sync-digest.md` keeps the latest 30 change-bearing
  reports, with bounded excerpts, provider text indented as code, and full-log links. It is a
  reading aid, never an acknowledgement.
- **Real publication runs only from `main`.** A feature branch can only dry-run.

## Risks and accepted costs

- **More bot commits on main.** Every successful run now lands a snapshot. Measured: 5–6 real
  runs a day, about half of them quiet, so main gains roughly twice as many bot commits. The
  spec accepts per-fixture `fetchedAt` churn.
- **PR #39 conflicts after every run**, not only change-bearing ones. It must refresh its
  generated data and merge inside one cron interval.
- **A red run no longer proves nothing shipped.** A merge not observed in 600 s, a closed PR or
  a rejected dispatch ends red, sometimes after the snapshot merged. Measured headroom: the
  seven bot merges since PR #28 took 48–146 s from open to merge. With "Allow auto-merge" off,
  every run goes red. `../Sportsbooks/CLAUDE.md` reads any red run as "re-verify every open
  position". That's over-verification, the safe direction; row 48 asks whether to distinguish
  publication from data failure.
- **Dispatch is not deployment.** The Pages run and the live header are the proof.
- **Digest reach:** 30 entries at the measured 2–3 change-bearing runs a day is about 10–15
  days. Older reports stay in Git history, and Actions logs follow retention.
- **PR body size (pre-existing):** the full log is inlined with no cap. The largest recent body
  is 26,046 characters against GitHub's 65,536 limit.
- **Step 0 exposure:** the new kinds and quiet freshness help Step 0. Items 1, 2 and 4 above are
  misleading lines in the audit trail, never in the app. The Step 0 contract already requires
  primary-source re-verification of every relevant line.
