# Kickoff

Big-5 European football fixtures, in Brooklyn time. Supports the betting work in
`../Sportsbooks/`.

**v0.0.1** — La Liga, Premier League, Serie A, Ligue 1, Bundesliga, plus the UEFA Super Cup
and the English, French and German domestic super cups.

## The one idea

Fixture data is **generated and diffed, never typed.**

This project replaces a hand-maintained single-file dashboard. An audit of that file on
23 Aug 2026 found ~20 wrong rows: the entire Ligue 1 opening matchday was a day early, the
Bundesliga opener was six hours off, one fixture had never existed at all, and PSG–Rennes was
listed with the wrong team at home after the LFP relocated it — which inverts the moneyline.

None of those were rendering bugs. They were all data-provenance bugs, so that is what the
architecture addresses:

- **The stored fact is a UTC instant** (`kickoffUtc`), not a calendar date plus a local time
  string. Stadium-local and Brooklyn times are both *derived*, so they cannot disagree with
  each other or with the source. Storing them separately is what let a whole matchday sit one
  day early with nothing to contradict it.
- **Every sync diffs against the previous snapshot** and reports what moved — dates, times,
  venues, status, and home/away swaps. It exits non-zero when something within 72 hours
  changed. A relocation surfaces instead of rotting.
- **The provider's flag for an unset kickoff time is honoured.** Fixtures where the league has
  fixed the date but not the hour render as "time not yet set", never as a confident number.
- **The snapshot is committed**, so git history is the fixture-change audit trail.

## Commands

```bash
npm run dev            # dev server with HMR
npm run sync           # refresh fixtures from the provider; exits 1 if something near-term moved
npm run sync -- --check   # report changes without writing
npm test               # vitest
npm run build          # static bundle in dist/
npm run build:single   # one self-contained dist-single/index.html, opens by double-click
```

`sync` accepts `--from=YYYY-MM-DD` and `--to=YYYY-MM-DD`; the default window is −30 to +150 days.

## Layout

```
src/lib/schema.ts        Zod schemas + the Fixture type. Identity lives here.
src/lib/time.ts          Timezone rendering. Formats instants; never parses local wall-clock.
src/lib/competitions.ts  Competition metadata: colours, zones, US broadcasters, provider codes.
src/lib/fixtures.ts      Loads and validates the snapshot; grouping and query helpers.
src/data/fixtures.json   GENERATED by `npm run sync`. Do not hand-edit.
scripts/providers/espn.ts  Fetch + normalize, behind a FixtureProvider interface.
scripts/diff.ts          Snapshot comparison. The safety net.
scripts/sync.ts          Orchestrator: fetch -> validate -> preserve notes -> diff -> write.
tests/                   DST boundaries, the normalizer, and one case per audited bug class.
```

## Data source

ESPN's public scoreboard API — no key, no auth.

```
GET site.api.espn.com/apis/site/v2/sports/soccer/{code}/scoreboard?dates=YYYYMMDD-YYYYMMDD
```

Two traps worth knowing:

1. **It caps responses at 100 events and does not say so.** A four-month range for La Liga
   silently returns only the first 100 fixtures. The provider therefore requests the window in
   28-day chunks and warns loudly if any chunk comes back at the cap.
2. **Some venue strings are wrong.** Rayo Vallecano's home fixtures are currently tagged
   *Estadio Municipal de Butarque* (Leganés's ground). Venue is cosmetic here and is not
   corrected by hand — hand-correcting generated data is the habit this project exists to
   break. A second provider in 0.0.2 is the right fix.

Fixture ids are the provider's own event id, namespaced by competition. They are *not* built
from team names: a season contains both legs of every pairing, so a name-derived id makes the
reverse fixture look like an inversion of the first.

## Not in 0.0.1

- **Betting overlays.** Fixtures carry stable ids so a later `positions.json` / `tokens.json`
  can join on them — the token-expiry-vs-kickoff map is the obvious next feature.
- **A second data source.** The `FixtureProvider` interface is in place; cross-checking two
  providers and surfacing disagreement rather than averaging it is 0.0.2.
- **Matchday numbers.** ESPN exposes none, and a round cannot be inferred from dates alone —
  La Liga's 2026-27 opening round ran 15–27 Aug and interleaved with matchday 2. Inventing one
  would be the exact failure mode this rewrite removes.
- **Scheduled sync.** Run it by hand for now; a `launchd` job is straightforward later.
